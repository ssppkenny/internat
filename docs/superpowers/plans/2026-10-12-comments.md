# Comments (Artalk) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Readers of the book site can leave anonymous comments under every page (except the print view) via a self-hosted Artalk server on the user's VPS at `comments.spkenny.ru`.

**Architecture:** A single Artalk v2.10.0 Go binary runs under systemd on the VPS, bound to `127.0.0.1:23366`, with SQLite storage; the existing nginx reverse-proxies `comments.spkenny.ru` to it and certbot provides TLS. The book site loads the Artalk client assets from the server via a small `custom.js` in the mdBook theme and mounts the widget on every page except `print.html`.

**Tech Stack:** Artalk v2.10.0 (server + embedded client assets), nginx + certbot, systemd, mdBook v0.5.4 theme JS (`additional-js`), pytest.

**Spec:** `docs/superpowers/specs/2026-10-12-comments-design.md`

## Global Constraints

- Never modify `internat/outline/` or `Photos/`; never stage `internat/settings.txt`.
- Artalk pinned to **v2.10.0**; linux amd64 tarball
  `https://github.com/ArtalkJS/Artalk/releases/download/v2.10.0/artalk_v2.10.0_linux_amd64.tar.gz`,
  sha256 `8ef3dcb322207ea76038a32d8e137604eba9313259c3423683d80efbcf18aed1`.
- Server binds `127.0.0.1:23366` only; nginx vhost `comments.spkenny.ru`;
  TLS via `certbot --nginx`; Cloudflare A record stays **DNS-only** (already added).
- Client assets are served by the Artalk server itself:
  `https://comments.spkenny.ru/dist/Artalk.js` and `/dist/Artalk.css`.
- Site wiring: `additional-js = ["theme/custom.js"]` in `site/book.toml`
  (paths are relative to `site/`, same convention as the existing
  `additional-css = ["theme/custom.css"]`); the file lives at `site/theme/custom.js`.
- Widget appears on every page **except** when `location.pathname` ends with
  `print.html`; heading text exactly `Комментарии`.
- `Artalk.init` parameters exactly: `el: "#artalk-comments"`,
  `server: "https://comments.spkenny.ru"`, `site: "Интернат"`,
  `pageKey: location.pathname`, `pageTitle: document.title`, `locale: "ru"`.
- Dark mode for mdBook html classes `coal`, `navy`, `ayu` (detected via
  `classList.contains` on `<html>`); live-updates via a MutationObserver on the
  `<html>` class attribute.
- Server config: `trusted_domains: [https://ssppkenny.github.io]`,
  `locale: ru`, `timezone: Europe/Moscow`, `site_default: Интернат`,
  `http.proxy_header: X-Forwarded-For`, SQLite `./data/artalk.db`, log enabled.
- Comments publish immediately; no captcha/social login initially.
- CSS addition exactly: `#artalk-comments { margin-top: 1.5em; }`.
- Deploy order: the user deploys and verifies the server first; pushing the
  site change is gated on explicit user confirmation. No workflow changes.
- Tests: `python3 -m pytest tests/ -v` from repo root, expected **41 passed**
  (40 existing + 1 new). Commits short and imperative.
- `tools/version_from_git.py` only counts `internat/outline` commits, so this
  feature's commits do not bump the book version.

- [ ] **Step 4: Create `site/theme/custom.js`**

```js
(function () {
  if (location.pathname.endsWith("print.html")) return;

  function mount() {
    var main = document.querySelector("main");
    if (!main) return;
    var heading = document.createElement("h2");
    heading.textContent = "Комментарии";
    var container = document.createElement("div");
    container.id = "artalk-comments";
    main.appendChild(heading);
    main.appendChild(container);

    var link = document.createElement("link");
    link.rel = "stylesheet";
    link.href = "https://comments.spkenny.ru/dist/Artalk.css";
    document.head.appendChild(link);

    var script = document.createElement("script");
    script.src = "https://comments.spkenny.ru/dist/Artalk.js";
    script.onload = function () {
      var artalk = Artalk.init({
        el: "#artalk-comments",
        server: "https://comments.spkenny.ru",
        site: "Интернат",
        pageKey: location.pathname,
        pageTitle: document.title,
        locale: "ru"
      });
      function isDark() {
        var classList = document.documentElement.classList;
        return classList.contains("coal") || classList.contains("navy") || classList.contains("ayu");
      }
      function apply() {
        artalk.setDarkMode(isDark());
      }
      apply();
      new MutationObserver(apply).observe(document.documentElement, {
        attributes: true,
        attributeFilter: ["class"]
      });
    };
    document.body.appendChild(script);
  }

  if (document.readyState === "loading") {
    document.addEventListener("DOMContentLoaded", mount);
  } else {
    mount();
  }
})();
```

- [ ] **Step 1: Create `docs/comments-deploy.md` with exactly this content**

````markdown
# Deploying the Artalk comment server (comments.spkenny.ru)

Run these steps over SSH on the VPS (204.168.247.247) as a user with sudo.
Prerequisites: nginx already installed and running; ports 80/443 open; the
Cloudflare A record `comments.spkenny.ru` already exists and is **DNS-only**
(grey cloud) — keep it that way.

## 1. Install the Artalk binary (v2.10.0)

```bash
cd /tmp
curl -fsSLO https://github.com/ArtalkJS/Artalk/releases/download/v2.10.0/artalk_v2.10.0_linux_amd64.tar.gz
curl -fsSLO https://github.com/ArtalkJS/Artalk/releases/download/v2.10.0/checksums.txt
grep linux_amd64 checksums.txt
sha256sum artalk_v2.10.0_linux_amd64.tar.gz
tar -xzf artalk_v2.10.0_linux_amd64.tar.gz
sudo install -m 0755 artalk_v2.10.0_linux_amd64/artalk /usr/local/bin/artalk
artalk --version
```

The sha256 must be
`8ef3dcb322207ea76038a32d8e137604eba9313259c3423683d80efbcf18aed1`;
`artalk --version` must print `Artalk (v2.10.0)`.

## 2. Service user and directories

```bash
sudo useradd --system --home /var/lib/artalk --shell /usr/sbin/nologin artalk
sudo mkdir -p /var/lib/artalk/data
sudo chown -R artalk:artalk /var/lib/artalk
```

## 3. Configuration /var/lib/artalk/artalk.yml

```bash
KEY=$(openssl rand -hex 16)
sudo tee /var/lib/artalk/artalk.yml >/dev/null <<EOF
host: 127.0.0.1
port: 23366
app_key: $KEY
locale: ru
timezone: Europe/Moscow
db:
  type: sqlite
  file: ./data/artalk.db
site_default: Интернат
trusted_domains:
  - https://ssppkenny.github.io
http:
  proxy_header: X-Forwarded-For
log:
  enabled: true
  filename: ./data/artalk.log
EOF
sudo chown artalk:artalk /var/lib/artalk/artalk.yml
```

## 4. systemd service

```bash
sudo tee /etc/systemd/system/artalk.service >/dev/null <<'EOF'
[Unit]
Description=Artalk comment server
After=network.target

[Service]
User=artalk
WorkingDirectory=/var/lib/artalk
ExecStart=/usr/local/bin/artalk server
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now artalk
systemctl status artalk --no-pager
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:23366/
```

Expect `302` from curl. The startup log shows an `ERROR ... [Email] Email
Sender initialize failed` line — that is expected and harmless (email
notifications are not configured).

## 5. Create the admin account

```bash
sudo -u artalk /usr/local/bin/artalk admin -w /var/lib/artalk \
  --name admin --email YOUR_EMAIL --password 'YOUR_PASSWORD'
```

The password lands in your shell history — run `history -d <n>` afterwards if
that matters to you. (Interactive mode needs a real terminal; do not pipe it.)

## 6. nginx + TLS

```bash
sudo tee /etc/nginx/sites-available/comments.spkenny.ru >/dev/null <<'EOF'
server {
    listen 80;
    server_name comments.spkenny.ru;

    location / {
        proxy_pass http://127.0.0.1:23366;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF
sudo ln -s /etc/nginx/sites-available/comments.spkenny.ru /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d comments.spkenny.ru
```

If your nginx keeps vhosts in `conf.d/` instead of `sites-available/`, put
the same server block there and reload.

## 7. Verify

```bash
curl -I https://comments.spkenny.ru
```

Expect `HTTP/2 302` (or 200) with a valid certificate. Open
`https://comments.spkenny.ru` in a browser and log in with the admin account;
the dashboard appears. Captcha, notifications, and social login can be enabled
later from the dashboard — no server changes needed.

## Upgrading Artalk later

Download the newer release tarball, verify its checksum, `sudo install` it
over `/usr/local/bin/artalk`, then `sudo systemctl restart artalk`.

## Rollback

`sudo systemctl disable --now artalk` stops comments; the site widget will
show a loading error until the repo-side `additional-js` line is removed.
````
